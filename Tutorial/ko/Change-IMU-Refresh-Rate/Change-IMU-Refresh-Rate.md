# IMU 모듈의 출력 레이트 변경하기

**핵심:** **시리얼로는 10–100 Hz로 설정할 수 있고, I²C로는 설정할 수 없습니다 — 약 115–118 Hz로 고정되어 있습니다.** 설정값은 flash에 저장되어 전원이 꺼져도 유지됩니다.

---

## 1. 시리얼: 설정 방법

### 프레임 형식

```
7E 23 07 60 <rate in Hz> 5F <checksum>
```

| 필드 | 값 |
|-|-|
| 헤더 | `7E 23` |
| 길이 | **고정 `0x07`** (총 7 bytes) |
| 기능 | **`0x60`** = 데이터 출력 레이트 설정 |
| 파라미터 1 | 레이트, **10–100 Hz** |
| 파라미터 2 | **고정 `0x5F`** |
| 체크섬 | `7E`부터 `5F`까지의 합, 하위 바이트 |

> ⚠️ **파라미터 2의 `0x5F`를 빼먹지 마세요.** 이것이 없으면 길이와 체크섬이 모두 틀려지고, 모듈은 **오류도 보고하지 않고 실패 응답도 보내지 않으며 — 프레임 전체를 조용히 무시합니다**. 그래서 모듈이 레이트를 바꿀 수 없다고 잘못 결론짓기 쉽습니다.

### 자주 쓰는 프레임

| 레이트 | 전체 프레임 |
|-|-|
| 10 Hz | `7E 23 07 60 0A 5F 71` |
| **20 Hz** | `7E 23 07 60 14 5F 7B` |
| 25 Hz | `7E 23 07 60 19 5F 80` |
| 50 Hz | `7E 23 07 60 32 5F 99` |
| 100 Hz | `7E 23 07 60 64 5F CB` |

### 전송 방법

- **시리얼 터미널**: 115200 8N1, 위 hex 바이트를 그대로 전송합니다.
- **공식 라이브러리**: `IMU_Serial_Library`의 `set_report_rate(hz)`.
- 설정이 적용될 때까지 약 1초 기다립니다.

---

## 2. 측정 결과

| 설정 | 프레임 도착 레이트 | **실효 출력 레이트** | 최장 연속 반복 횟수 |
|-|-|-|-|
| 20 Hz | 20.8 Hz | **20.7 Hz** | 1 (반복 없음) |
| 50 Hz | 52.9 Hz | **52.8 Hz** | 1 |
| 100 Hz | 105.6 Hz | **104.0 Hz** | 2 |

두 가지 관찰:

1. **실효 출력 레이트 ≈ 도착 레이트**입니다. 이는 모듈 내부의 fusion이 실제로 설정된 레이트로 동작한다는 뜻이며, **낮은 레이트에서도 같은 프레임을 계속 재전송하지 않습니다**.
2. 실제 값은 설정값보다 **3–8% 높게** 나옵니다 (20 설정 시 20.8, 100 설정 시 105.6). 이는 모듈 자체의 클록 오차이며 정상입니다.

---

## 3. 설정은 전원이 꺼져도 유지되나요?

20 Hz로 설정 → Type-C를 3초간 분리 → 다시 연결 → 재측정: **여전히 20.7 Hz**.

**설정은 flash에 저장되므로 한 번만 설정하면 충분합니다** — 전원을 켤 때마다 다시 보낼 필요가 없습니다.

> 따라서: **새 모듈은 공장 기본값인 25 Hz로 출고**되므로, 처음 설치할 때 한 번 설정하고 확인해 두면 그 뒤로는 신경 쓸 필요가 없습니다.

---

## 4. I²C: 변경 불가

세 가지 검증을 모두 수행했습니다:

| 검증 | 결과 |
|-|-|
| 시리얼로 20 Hz 설정 후 I²C로 레지스터 `0x16` 폴링 | 쿼터니언이 여전히 **115.4 Hz**로 변함 (115.8 Hz로 폴링) → **변화 없음** |
| 지연 없이 최대한 빠르게 폴링(1779 Hz)하고 반복 길이의 중앙값 확인 | **~111 Hz**에 해당 → 고정 레이트 |
| I²C로 레지스터 `0x60 = 20`을 직접 기록 | 레이트 **변화 없음**; `0x60`은 항상 `0`으로 읽힘 |

**결론: 어떤 인터페이스로도 I²C 레이트를 바꿀 수 없으며, 약 115–118 Hz로 고정되어 있습니다.** "최대값으로 제한된" 것이 아니라, 이것이 모듈의 고정된 fusion 출력 레이트입니다.

## 5. 꼭 알아야 할 점: 너무 빠르게 폴링하면 torn 값이 반환됩니다

471 Hz로 폴링하면서 연속 두 번의 읽기가 동일한지 세어 보면, 반복 길이 분포는 다음과 같습니다:

```
length 1: 333 times     ← read the middle of a register update
length 3: 114 times     ← normal
length 4: 182 times     ← normal
```

471 ÷ 4 ≈ 118 Hz로, 리프레시 레이트와 일치합니다. **길이 1인 333회의 읽기는 torn**입니다 — 모듈이 16-byte 레지스터 블록을 갱신하는 동안 읽어서 절반은 이전 값, 절반은 새 값이 섞인 것입니다.

**위험한 점은 torn 쿼터니언도 여전히 유효한 단위 쿼터니언이라는 것입니다** (인접한 두 자세의 차이가 약 9 ms에 불과해 혼합 결과가 매우 비슷합니다). 따라서 norm 검사로는 잡아낼 수 없습니다.

👉 **150 Hz보다 훨씬 빠르게 폴링하지 마세요.** 50–100 Hz가 가장 안정적이며, 이는 정확히 MicroDuck의 제어 루프(50 Hz)와 IMU 스레드(100 Hz)의 범위입니다.

## 6. MicroDuck에 있어서의 의미

| | |
|-|-|
| **I²C 경로** (모듈을 HAT의 I²C 헤더에 연결) | **레이트 설정 불필요**; 고정된 ~115 Hz로 이미 충분합니다 |
| 시리얼 경로 레이트 | 자동 시리얼 출력에만 영향을 주며, I²C가 반환하는 값과는 무관합니다 |
| 문서의 "공장 출하 시 100 Hz, 새 모듈에서 확인" | **시리얼 사용자에게만 해당**됩니다; I²C 사용자는 신경 쓰지 않아도 됩니다 |
