# IMUモジュールの出力レートを変更する

**結論：** **シリアルでは 10〜100 Hz に設定できますが、I²C では変更できません — 約 115〜118 Hz に固定されています。** 設定はフラッシュに保存され、電源を切っても保持されます。

---

## 1. シリアル：設定方法

### フレームフォーマット

```
7E 23 07 60 <rate in Hz> 5F <checksum>
```

| フィールド | 値 |
|-|-|
| ヘッダー | `7E 23` |
| 長さ | **固定 `0x07`**（全 7 バイト） |
| ファンクション | **`0x60`** = データ出力レートの設定 |
| パラメータ 1 | レート、**10〜100 Hz** |
| パラメータ 2 | **固定 `0x5F`** |
| チェックサム | `7E` から `5F` までの合計、下位バイト |

> ⚠️ **パラメータ 2 の `0x5F` を省略しないでください。** 省略すると長さとチェックサムの両方が不正になり、モジュールは**エラーも返さず失敗応答も返さず — フレーム全体を黙って無視します**。そのため「このモジュールはレートを変更できない」と誤って結論しやすくなります。

### よく使うフレーム

| レート | フレーム全体 |
|-|-|
| 10 Hz | `7E 23 07 60 0A 5F 71` |
| **20 Hz** | `7E 23 07 60 14 5F 7B` |
| 25 Hz | `7E 23 07 60 19 5F 80` |
| 50 Hz | `7E 23 07 60 32 5F 99` |
| 100 Hz | `7E 23 07 60 64 5F CB` |

### 送信方法

- **シリアルターミナル**：115200 8N1 で、上記の 16 進バイトをそのまま送信します。
- **公式ライブラリ**：`IMU_Serial_Library` の `set_report_rate(hz)`。
- 設定が反映されるまで約 1 秒待ちます。

## 2. 実測結果

| 設定 | フレーム到達レート | **実効出力レート** | 最長連続同一値 |
|-|-|-|-|
| 20 Hz | 20.8 Hz | **20.7 Hz** | 1（繰り返しなし） |
| 50 Hz | 52.9 Hz | **52.8 Hz** | 1 |
| 100 Hz | 105.6 Hz | **104.0 Hz** | 2 |

得られた知見は 2 点です：

1. **実効出力レート ≈ 到達レート**。つまりモジュール内部のフュージョンは設定したレートで実際に動作しており、**低レートでも同じフレームを再送し続けることはありません**。
2. 実測値は設定より **3〜8% 高め** になります（20 に設定して 20.8、100 に設定して 105.6）。これはモジュール自身のクロック許容誤差であり、正常です。

---

## 3. 設定は電源オフ後も保持されるか？

20 Hz に設定 → Type-C を 3 秒間抜く → 再接続 → 再測定：**依然として 20.7 Hz**。

**設定はフラッシュに保存されるため、一度設定すれば十分です** — 電源投入のたびに再送する必要はありません。

> 補足：**新しいモジュールは工場出荷時のデフォルト 25 Hz で出荷されます**。初回設置時に一度設定して確認してください。その後は気にする必要はありません。

---

## 4. I²C：変更不可

3 つの検証をすべて実施しました：

| 検証 | 結果 |
|-|-|
| シリアルで 20 Hz に設定した後、I²C でレジスタ `0x16` をポーリング | クォータニオンは依然として **115.4 Hz** で変化（115.8 Hz でポーリング）→ **変化なし** |
| 遅延なしで可能な限り高速にポーリング（1779 Hz）し、同一値の連続長の中央値を確認 | **約 111 Hz** に相当 → 固定レート |
| I²C でレジスタ `0x60 = 20` を直接書き込み | レートは**変化なし**；`0x60` は常に `0` を読み返す |

**結論：どのインターフェースでも I²C のレートは変更できません。約 115〜118 Hz に固定されています。** 「上限まで絞られている」のではなく、モジュールの固定されたフュージョン出力レートなのです。

---

## 5. 必ず知っておきたいこと：速すぎるポーリングは破損した値を返す

471 Hz でポーリングしながら、連続する 2 回の読み取りが同一かどうかを数えると、連続長の分布は次のようになります：

```
length 1: 333 times     ← read the middle of a register update
length 3: 114 times     ← normal
length 4: 182 times     ← normal
```

471 ÷ 4 ≈ 118 Hz となり、リフレッシュレートと一致します。**長さ 1 の 333 回の読み取りは破損値（torn）** です — モジュールが 16 バイトのレジスタブロックを更新している最中に読み取られた、半分古く半分新しい値です。

**危険なのは、破損したクォータニオンも依然として有効な単位クォータニオンであることです**（隣接する姿勢の差は約 9 ms しかないため、混ざり合った値はごく近い値になります）。そのためノルムチェックでは検出できません。

👉 **150 Hz よりずっと速くポーリングしないでください。** 50〜100 Hz が最も安定しており、これはまさに MicroDuck の制御ループ（50 Hz）と IMU スレッド（100 Hz）の範囲です。

## 6. MicroDuck にとっての意味

| | |
|-|-|
| **I²C 経路**（モジュールを HAT の I²C ヘッダーに接続） | **レート設定は不要**；固定の約 115 Hz で十分 |
| シリアル経路のレート | 自動シリアル出力にのみ影響し、I²C が返す値とは無関係 |
| ドキュメントの「工場出荷時 100 Hz、新しいモジュールで確認を」 | **シリアル利用者にのみ関係**；I²C 利用者は気にする必要はありません |
